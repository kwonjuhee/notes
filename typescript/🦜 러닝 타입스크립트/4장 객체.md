
## 객체 타입

- 객체 리터럴 문법으로 객체를 생성하면 타입스크립트는 해당 속성을 기반으로 새로운 객체 타입 또는 타입 형태를 고려한다.
- 객체 타입은 해당 객체의 값과 동일한 속성명과 원시 타입을 갖는다.
- 존재하지 않는 속성에 접근하려고 하는 경우 타입 오류가 발생한다.

### 객체 타입 선언

- 기존 객체에서 타입이 유추되지만 명시적으로 선언할 수도 있다.

```tsx
let poetLater: {
  born: number;
  name: string;
};

poetLater = {
  born: 1925,
  name: "Mary Oliver",
};

poetLater = "aaa";
// Error: Type 'string' is not assignable to type '{ born: number; name: string; }'.
```

### 별칭 객체 타입

- 타입 별칭을 할당해 사용하는 것이 더 일반적이다. 할당 가능성 오류 메세지를 좀 더 직접적으로 읽기 쉽게 만든다.

```tsx
type Poet = {
  born: number;
  name: string;
};

let poetLater: Poet;

poetLater = "aaa";
// Error: Type 'string' is not assignable to type 'Poet'.
```


## 구조적 타이핑

타입스크립트의 타입 시스템은 **구조적으로 타입화 (structually typed)**되어 있다.

- 타입을 충족하는 모든 값을 해당 타입의 값으로 사용할 수 있다.
- 매개변수나 변수가 특정 객체 타입으로 선언되면 타입스크립트에 어떤 객체를 사용하든 해당 속성이 있어야 한다.

```tsx
let WithFirstName = {
  firstName: string;
};

let WithLastName = {
  lastName: string;
};

const hasBoth = {
  firstName: "주희",
  lastName: "권",
};

// Ok: hasBoth는 string 타입의 firstName을 포함한다. 
let withFirstName: WithFirstName = hasBoth;

// Ok: hasBoth는 string 타입의 lastName을 포함한다. 
let withLastName: WithLastName = hasBoth;
```

- 덕 타이핑(duck typing)과는 다르다.
    - 타입스크립트의 타입 검사기에서 구조적 타이핑은 정적 시스템이 타입을 검사하는 경우다.
    - 덕 타이핑은 런타임에서 사용될 때까지 객체 타입을 검사하지 않는 것을 말한다.
    - 자바스크립트는 duck typed인 반면 타입스크립트는 structually typed된다.

### 사용 검사

- 타입 애너테이션된 위치에 값을 제공할때 값을 해당 객체 타입에 할당할 수 있는지 확인한다.
- 객체 타입의 필수 멤버가 객체에 없다면 타입 오류를 발생시킨다.
    
    ```tsx
    let FirstAndLastNames = {
      first: string;
      last: string;
    };
    
    const hasBoth: FirstAndLastNames = {
      first:"주희",
      last: "권",
    };
    
    // first, last 두 가지 속성이 모두 있어야 함
    const hasOnlyOne: FirstAndLastNames = {
    	// Error: Property 'last' is missing in type { first: string }
    	// but required in type 'FirstAndLastName'
      first: "주희"
    }
    ```
    
- 일치하지 않는 타입도 허용되지 않는다.
    
    ```tsx
    type TimeRange = {
      start: Date;
    }
    
    const hasStartString: TimeRange = {
      // Error: string 타입은 Date 타입에 할당할 수 없다.
      start: "1879-02-13",
    }
    ```
    

### 초과 속성 검사

- 객체 타입으로 선언된 변수의 초기값에 객체 타입에서 **정의된 것보다 많은 필드가 있다면 타입 오류가 발생**한다.
- 초과 속성 검사는 객체 타입으로 **선언된 위치에서 생성되는 객체 리터럴에 대해서만** 일어난다. **기존 객체 리터럴을 할당하면 초과 속성 검사를 우회**한다.

```tsx
type Poet = {
  born: number;
  name: string;
};

// 객체 타입으로 선언
const extraProperty: Poet = {
	activity: "walking",
  // Error: Type '{ activity: string; born: number; name: string; }' is not assignable to type 'Poet'.
  // Object literal may only specify known properties, and 'activity' does not exist in type 'Poet'.
	born: 1935,
	name: " Marh Oliver",
}

// 구조적으로 일치하므로
const existingObject = {
  activity: "walking",
  born: 1935,
  name: "Mary Oliver",
};

const extraPropertyButOk: Poet = existingObject; // ok
```

- 초과 속성을 금지하면 코드를 깨끗하게 유지할 수 있고 예상한대로 동작하도록 할 수 있다. 선언되지 않은 초과 속성은 종종 잘못 입력된 속성 이름이거나 사용되지 않는 코드일 수 있기 때문에

### 중첩된 객체 타입

```tsx
type Poem = {
  author: {
    firstName: string;
    lastName: string;
  };
  name: string;
};

const poemMatch: Poem = {
  author: {
    firstName: "주희",
    lastName: "권",
  },
  name: "lllll";
};

const poemMismatch: Poem = {
	author: {
		name: "권주희",
		// 초과 속성 검사로 인한 Error
	},
	name: "lllll",
};
		
```

- 중첩된 타입을 타입 별칭으로 추출
    - 고유한 타입 이름을 부여하면 코드와 타입 오류 메시지를 읽기 더 쉬워진다.
    
    ```tsx
    type Author = {
      firstName: string;
      lastName: string;
    };
    
    type Poem = {
      author: Author;
      name: string;
    }
    
    const poemMismatch: Poem = {
    	author: {
    		name: "권주희",
    		// 초과 속성 검사로 인한 Error
    		// 타입 { name: string }은 타입 Author에 할당할 수 없다.
    	},
    	name: "lllll",
    };
    ```
    

### 선택적 속성

- 타입의 속성 애너테이션에서 ?를 추가하여 선택적 속성임을 나타낼 수 있다.
    
    ```tsx
    type Book = {
    	author?: string;
    	pages: number;
    }
    
    const ok: Book = {
    	author: "Rita Dove",
    	pages: 80,
    };
    
    const missing: Book = {
    	// Error: Property 'pages' is missing in type '{ author: string; }' but required in type 'Book'.
    	author: "Rita Dove",
    };
    ```
    
- 선택적 속성과 **undefined를 포함한 유니언 타입의 속성에는 차이가 있다.**
    - 선택적 속성은 존재하지 않아도 된다.
    - | undefined는 값이 undefined일지라도 반드시 존재해야한다.
    
    ```tsx
    type Writers = {
      author: string | undefined;
      editor?: string;
    };
    
    // Ok: author는 undefined로 제공됨
    const hasRequired: Writers = {
      author: undefined,
    };
    
    // Error: Property 'author' is missing in type '{}' but required in type 'Writers'.
    const missingRequired: Writers = {};
    ```
    

## 객체 타입 유니언

### 유추된 객체 타입 유니언

- 변수에 **여러 객체 타입 중 하나가 될 수 있는 초기값**이 주어지면 타입스크립트는 해당 타입을 **객체 타입 유니언으로 간주**한다.
- 유니언 타입은 가능한 각 객체 타입을 구성하고 있는 요소를 모두 가질 수 있다.
- 객체 타입에 각각 정의된 속성은 비록 초기값이 없는 선택적 타입이지만 각 객체 타입의 구성 요소로 주어진다. rhymes? : undefined / pages? : undefined

```tsx
const poem = Math.random() > 0.5
  ? { name: "The Double Image", pages: 7 }
  : { name: "Her Kind", rhymes: true };

/** 타입
{
  name: string;
  pages: number;
  rhymes?: undefined;
}
| {
  name: string;
  pages?: undefined;
  rhymes: boolean;
}
*/

poem.name; // string
poem.pages; // number | undefined
poem.rhymes; // boolean | undefined
```

### 명시된 객체 타입 유니언

- 객체 타입의 조합을 명시하면 객체 타입을 더 명확히 정의할 수 있다. **유니언을 구성하는 모든 객체 타입에 존재하는 속성에 대한 접근만 허용**한다.

```tsx
type PoemWithPages = {
  name: string;
  pages: number;
};

type PoemWithRhymes = {
  name: string;
  rhymes: boolean;
};

type Poem = PoemWithPages | PoemWithRhymes;

const poem: Poem = Math.random() > 0.5
	? { name: "aaa", pages: 7 }
	: { name: "aaa", rhymes: true };

// name과 달리 pages와 rhymes는 항상 존재한다는 보장이 없다.
poem.name; // Ok
poem.pages;
// Error: Property 'pages' does not exist on type 'Poem'.
// Property 'pages' does not exist on type 'PoemWithRhymes'.
poem.rhymes;
// Error: Property 'rhymes' does not exist on type 'Poem'.
//  Property 'rhymes' does not exist on type 'PoemWithPages'.
```

- 잠재적으로 존재하지 않는 (존재가 보장되지 않는) 객체 멤버에 대한 접근을 제한하여 코드의 안전을 지킬 수 있다.
- **존재가 보장되지 않는 속성에 접근하기 위해서는 타입을 좁혀야 한다.**

### 객체 타입 내로잉

- 타입 검사기가 유니언 타입 값에 특정 속성이 포함된 경우에만 코드 영역을 실행할 수 있음을 알게 되면, 값의 타입을 해당 속성을 포함하는 타입으로 좁힌다.
- 즉, 객체의 형태를 확인하고 타입 내로잉이 객체에 적용된다.
- 다음은 poem의 pages가 타입 가드 역할을 하여 PoemWithPages 타입임을 나타내는지 확인한다.
    
    ```tsx
    if ("pages" in poem) {
      poem.pages; // Ok: poem은 PoemWithPages로 좁혀짐
    } else {
      poem.rhymes; // Ok: poem은 PoemWithRhymes로 좁혀짐
    }
    
    if (poem.pages) { }
    // Error: Property 'pages' does not exist on type 'Poem'.
    //  Property 'pages' does not exist on type 'PoemWithRhymes'.
    ```
    
    - if (poem.pages)와 같은 형식으로 참 여부를 확인하는 것은 허용하지 않는다. 존재가 보장되지 않는 속성에 대한 접근이기 때문에 타입 오류로 간주된다.

### 판별된 유니언

- **객체의 속성이 객체의 형태를 나타내도록** 하는 것. 이러한 타입 형태를 **판별된 유니언(discriminated union)** 이라 부르고 객체의 타입을 가리키는 속성이 **판별값**이다.
- **판별 속성을 사용해 타입 내로잉을 수행**한다.
- 제네릭 데이터 운영을 위해 판별된 유니언을 사용할 수 있다.

```tsx
type PoemWithPages = {
  name: string;
  pages: number;
  type: 'pages';
};

type PoemWithRhymes = {
  name: string;
  rhymes: boolean;
  type: 'rhymes';
};

type Poem = PoemWithPages | PoemWithRhymes;

const poem = Math.random() > 0.5
  ? { name: "The Double Image", pages: 7 }
  : { name: "Her Kind", rhymes: true };

if (poem.type === "pages") { }
else { }

poem.type; // 'pages' | 'rhymes'

poem.pages; // Error
```

## 교차 타입 & (intersection type)

- 교차 타입은 여러 타입을 동시에 나타낸다.
- 여러 기존 객체 타입을 별칭 객체 타입으로 결합해 새로운 타입을 생성한다.
    
    ```tsx
    type Artwork = {
      genre: string;
      name: string;
    };
    
    type Writing = {
      pages: number;
      name: string;
    };
    
    type WrittenArt = Artwork & Writing;
    /**
    {
      genre: string;
      name: string;
      pages: number;
    }
    */
    ```
    
- 유니언 타입과 결합하여 하나의 타입으로 **판별된 유니언 타입을 설명하는 데 유용**하다.
    
    ```tsx
    type ShortPoem = { author: string } & (
      | { kigo: string; type: "haju"; }
      | { meter: number; type: "villanelle"; }
    );
    
    const morningGlory: ShortPoem = {
      author: "aaa",
      kigo: "Morning Glory",
      type: "haju",
    };
    
    const oneArt: ShortPoem = {
      // Error: 할당할 수 없다. meter 속성이 없다.
      author: "aaa",
      type: "villanelle",
    }
    ```
    

### 교차 타입의 위험성

교차 타입은 유용한 개념이지만 스스로나 타입스크립트 컴파일러를 혼동시키는 방식으로 사용하기 쉽다. 교차 타입을 사용할 때는 가능한 한 코드를 간결하게 유지하려고 하자.

- 복잡한 교차 타입을 만들게 되면 할당 가능성 오류 메시지가 길어져 읽기 어려워진다.
    - 타입 별칭으로 객체 타입을 분할하여 개선할 수 있다.
    
    ```tsx
    type ShortPoemBase = { author: string };
    type Haiku = ShortPoemBase & { kigo: string; type: "haiku" };
    type Villanelle = ShortPoemBase & { meter: number; type: "villanelle" };
    type ShortPoem = Haiku | Villanelle;
    ```
    
- 교차 타입은 잘못 사용하면 **불가능한 타입(never)을 생성**한다.
    - 원시 타입의 값은 동시에 여러 타입이 될 수 없기 때문에 교차 타입의 구성 요소로 함께 결합할 수 없다. type notPossible = number & string;
    
    ```tsx
    type T1 = number;
    type T2 = string;
    
    type notPossible = T1 & T2; // never 
    ```
