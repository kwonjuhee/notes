
타입스크립트가 읽은 값을 바탕으로 추론을 수행하는 개념

- **유니언(union)** : 값에 허용된 타입을 두 개 이상의 가능한 타입으로 확장하는 것
- **내로잉(narrowing)** : 값에 허용된 타입이 하나 이상의 가능한 타입이 되지 않도록 좁히는 것

## 유니언 타입

- 다음 mathematician은 `string | undefined` 타입
    
    ```tsx
    let mathematician = Math.random() > 0.5
    	? undefined
    	: "aaaa";
    ```
    
    - 타입 선언 순서는 중요하지 않다. ( = `undefined | string` )
    - 두 개 이상의 옵션 중 하나임을 나타낸다.

- 초기값이 있더라도 타입 애너테이션으로 유니언 타입임을 명시할 수 있다.
    
    ```tsx
    let thinker: string | null = null;
    
    thinker = "aaa"; // ok
    ```
    
- 멤버 속성에 접근하려고 할 때 유니언으로 선언한 타입 모두에 존재하는 멤버 속성에만 접근할 수 있다.
    
    ```tsx
    let physicist = Math.random() > 0.5
    	? "aaa"
    	: 84;
    
    physicist.toString(); //ok
    
    physicist.toUpperCase(); // Error: number 타입에 toUpperCase 프로퍼티가 존재하지 않음
    
    physicist.toFixed(); // Error: string 타입에 toFixed 프로퍼티가 존재하지 않음
    ```
    
    - 어떤 속성을 포함하는지 확실하지 않으므로 공통 속성만 허용하는 것
    - 하나의 타입에만 존재하는 속성을 사용하려면 타입스크립트에 구체적인 타입을 알려야한다. 이 과정을 내로잉이라 한다.

## 내로잉

- 내로잉은 정의, 선언, 유추된 것보다 더 구체적인 타입임을 코드에서 유추하는 것을 말한다.
- 타입스크립트가 값의 타입이 이전에 알려진 것보다 더 좁혀졌다는 것을 알게 되면 값을 더 구체적인 타입으로 취급한다.
- 타입을 좁히는 데 사용할 수 있는 논리적 검사를 **타입 가드(type guard)**라 한다.

### 타입 가드1. 값 할당을 통한 내로잉

변수에 값을 직접 할당하면 변수의 타입을 할당된 값의 타입으로 간주한다.

```tsx
let a = number | string;

a = "aaa"; // string 타입으로 할당되었으므로
a.toUpperCase(); // ok

a.toFixed(); // Error
```

### 타입 가드2. 조건 검사를 통한 내로잉

if문을 통해 변수가 알려진 값과 동일한지 확인함으로써 동일한 타입인지 확인한다.

```tsx
let scientist = Math.random() > 0.5
	? "aaa"
	: 51;

if (scientist === "aaa") {
	// scientist는 string 타입
	scientist.toUpperCase(); //ok
}
```

### 타입 가드3. typeof 검사를 통한 내로잉

직접 값을 확인하는 방법 대신 typeof 연산자를 통해 타입을 확인할 수 있다.

```tsx
let researcher = Math.random() > 0.5
	? "aaa"
	: 51;

if (typeof researcher === "string") {
	// scientist는 string 타입
	scientist.toUpperCase(); //ok
}
```

## 리터럴 타입

- 원시타입보다 구체적인 **특정 원시값**을 말한다.
	- 반대로 말하면 각 원시 타입은 해당 타입의 가능한 모든 리터럴 값의 집합
- **const로 선언**하고 리터럴 값을 할당하면 할당된 리터럴 값으로 유추

```tsx
const mathematician = "aaa"; // "aaa" 타입

let mathematician = "aaa"; // string 타입
```

- boolean, null, undefined 타입은 리터럴 타입이 없다.

### 리터럴 할당 가능성

동일한 원시 타입이어도 서로 다른 리터럴 타입이라면 할당할 수 없다.

```tsx
let specificallyA: "A";

specificallyA = "A"; // ok
specificallyA = "B"; // Error: 타입 "B"는 타입 "A"에 할당할 수 없다.

let someString = ""; // string;

specificallyA = someString; // Error: 타입 string은 "A" 타입에 할당할 수 없다.
```


## 엄격한 null 검사

다른 타입이 필요한 위치에서 null이나 undefined 값을 사용할 수 없게 한다.

strictNullChecks를 비활성화하면 타입스크립트 에러가 발생하지 않지만 런타임 에러가 발생할 가능성이 있다.

```tsx
let nameMaybe = Math.random() > 0.5
	? "aaa"
	: undefined;

nameMaybe.toLowerCase(); // 잠재적 런타임 에러
```

### 참 검사를 통한 내로잉

타입스크립트는 잠재적인 값 중 truthy로 확인된 일부에 한해서만 변수의 타입을 좁힐 수 있다.
- falsy(- false, 0, -0, 0n, “”, null, undefined, NaN)를 제외한 것들은 모두 참

```tsx
let geneticist = Math.random() > 0.5
	? "aaa"
	: undefined;

// undefined는 falsy 값이므로 if문에서 string 타입으로 추론된다.
if (geneticist) {
	geneticist.toUpperCase(); // ok: string
}

geneticist.toUpperCase(); // Error: possibly undefined
```

- 논리 연산자인 &&와 ?는 참 여부만 확인하고 내로잉을 수행하지는 않는다.

### 초기값이 없는 변수

- 초기값이 없는 변수는 값 할당 이전에 변수의 속성에 접근하려고 하면 오류가 발생한다.
- 타입 선언시 undefined가 포함되어 있는 경우에는 오류가 보고되지 않는다. undefined는 유효한 타입이기 때문에 사용전에는 정의할 필요가 없음을 타입스크립트에 나타낸다.

```tsx
let mathematician: string;

mathematician?.length;
// Error: mathematician 변수가 할당되기 전에 사용됨
```

```tsx
let mathematician: string | undefined;

mathematician?.length; // ok
```


## 타입 별칭 (type alias)

재사용하는 타입에 이름을 할당하는 것 `type 새로운 타입 = 타입`
- 복사해서 붙여넣기처럼 작동한다.

### 타입 별칭은 자바스크립트가 아니다.

- 타입 별칭은 자바스크립트가 아니고 타입 시스템에만 존재하므로 런타임에 참조할 수 없다.
- 타입스크립트는 런타임에 존재하지 않는 항목에 접근하려고 하면 타입 오류로 알려준다.

```ts
type SomeType = string | undefined;

console.log(SomeType);
// Error: 'SomeType' only refers to a type, but is being used as a value here.
```

### 타입 별칭 결합

- 타입 별칭은 다른 타입 별칭을 참조할 수 있다.

```tsx
type Id = number | string;

type IdMaybe = Id | undefined | null;
```

- 선언 전에 참조해도 된다.
