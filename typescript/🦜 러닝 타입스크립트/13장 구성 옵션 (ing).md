
## tsc 옵션

- `--noEmit` 옵션 : tsc를 실행할 때 js 파일 생성은 건너뛰고 타입 검사만 실행

## tsconfig 파일

- tsconfig 파일의 존재는 해당 디렉터리가 타입스크립트 프로젝트의 루트임을 나타낸다.
- vs code 같은 IDE는 IntelliSence 기능을 제공할 때 tsconfig의 구성을 따른다.
- `tsc --init`을 통해 파일 생성 가능

## 파일 포함

- 기본적으로 tsc는 현재 디렉터리와 하위 디렉터리에 숨겨지지 않은 모든 ts 파일에서 실행된다.
- 숨겨진 디렉터리와 node_modules 디렉터리는 무시한다.
- tsconfig의 include와 exclude 속성을 통해 실행할 파일 목록을 수정할 수 있다.

### include

- 컴파일에 포함할 디렉터리와 파일을 설명하는 문자열 배열 명시한다.
- glob 와일드카드 허용
	- `*` : 0개 이상의 문자와 일치 (디렉터리 구분자 제외)
	- `?` : 하나의 문자와 일치 (디렉터리 구분자 제외)
	- `**/` : 모든 레벨에 중첩된 모든 디렉터리와 일치
- 예시
	- `typings/**/*.d.ts` : typings 하위의 중첩된 디렉터리의 .d.ts 확장자 파일
	- `src/**/*??.*` : 확장자 앞의 파일명에 적어도 두개 이상의 문자를 가진 가진 src/ 하위의 파일만 허용

### exclude

- 타입스크립트로 컴파일할 수 없는 파일을 명시한다. include에서 생략된다.
- 단, 시작 목록에서 제거될 뿐 해당 파일을 import한 파일에서는 실행된다.


## 대체 확장자

### jsx 구문

- jsx 구문을 사용하기 위해서는 구성 옵션에서 jsx 컴파일러 옵션을 활성화하고 .tsx 확장자로 파일의 이름 지정해야 한다.
- jsx 컴파일러 옵션 입력과 출력

	| 값 | 입력 코드 | 출력 코드 | 출력 파일 확장자 |
	| --- | --- | --- | --- |
	| "preserve" | \<div /> | \<div /> | .jsx |
	| "react" | \<div /> | React.createElement("div") | .js |
	| "react-native" | \<div /> | \<div /> | .js |


### .tsx 파일의 제네릭 화살표 함수

- 제네릭 화살표 함수의 구문은 JSX 구문과 충돌한다. 타입 인수를 시작 태그로 이해하여 종료 태그가 없다는 구문 오류를 발생시킨다.
- 타입 인수의 기본값을 unknown으로 지정하여 JSX 요소가 아닌 타입 인수를 읽도록 지시할 수 있다.

### resolveJsonModule

- json 파일을 마치 객체를 내보내는 ts파일인 것처럼 가져오고 해당 객체의 타입을 const 변수인 것처럼 유추한다.
- esModuleInterop 컴파일러 옵션이 활성화된 경우에도 기본 가져오기를 사용할 수 있다.
- 객체가 포함된 JSON 파일이라면 구조 분해 import가 가능하지만 다른 리터럴 타입을 포함한 JSON 파일이라면 \*을 사용한다.


## 자바스크립트로 내보내기

- 타입스크립트를 자바스크립트로 컴파일하기 위해 바벨 대신 타입스크립트에서 의존하고 있는 프로젝트의 경우 사용하는 옵션들

### outDir

- `outDir` : 출력 파일의 루트 디렉터리를 지정하는 옵션 (기본적으로 출력 파일을 해당 소스 파일과 동일한 위치에 생성한다.)
- `rootDir` : 루트 디렉터리를 명시적으로 지정하는 옵션 (보통 `.` 아니면 `src`)

### target

- 자바스크립트 코드 구문을 어느 버전까지 변환해야 하는지를 지정하는 target 컴파일러 옵션을 제공한다.
- target을 지정하지 않으면 이전 버전과의 호환성을 위해 기본적으로 es3가 지정된다. 이렇게 오래된 환경에서 최신 자바스크립트 기능을 지원하려면 더 많은 자바스크립트 코드를 생성해야 하므로 파일 크기가 조금 더 커지고 런타임 성능이 약간 저하된다.

> 2022년 시점으로 전 세계 사용자의 0.1% 이상을 서비스하는 브라우저의 모든 배포 버전은 ECMA스크립트 2019, 거의 모든 ECMA 스크립트 2020~2021을 지원한다. 또한 LTS 버전의 Node.js는 모든 ECMA스크립트 2021을 지원한다. 그러므로 target을 적어도 "es2019" 이상으로 지정하지 않을 이유가 없다.

### 내보내기 선언

- 대부분의 패키지는 타입스크립트의 declaration 컴파일러 옵션을 사용해 소스 파일에서 .d.ts 출력 파일을 내보낸다.
- .js와 .jsx 파일없이 선언 파일만 내보내도록 지시하는 emitDeclarationOnly 컴파일러 옵션이 존재한다. 이는 외부 도구를 사용해 출력 js 파일을 생성하지만 타입스크립트를 사용해 출력 선언 파일을 생성하려고 할 때 유용하다.

### 소스 맵

- 소스 맵은 출력 파일의 내용이 원본 소스 파일과 어떻게 일치하는지에 대한 설명이다. 소스 맵은 출력 파일을 탐색할 때 디버거같은 개발자 도구에서 원본 소스 코드를 표시하도록 설정한다.
- 타입스크립트의 sourceMap 컴파일러 옵션을 사용하면 출력 파일과 함께 소스 맵을 출력하는 기능도 제공한다.
- declarationMap 컴파일러 옵션은 .d.ts 선언 파일에 대한 소스 맵을 생성할 수도 있다.

### noEmit

- js 파일 생성을 건너뛰고 온전히 타입 검사기로만 작동한다.


## 타입 검사

타입 검사기를 제어하는 구성 옵션들

### lib

- 타입스크립트가 런타임 환경에 있다고 가정하는 전역 API는 lib 컴파일러 옵션으로 구성할 수 있다.
- 브라우저 타입 포함을 나타내는 dom, target 컴파일러 옵션을 기본값으로 하는 문자열 배열을 사용한다.
- 언제 사용?
	- 브라우저에서 실행되지 않는 프로젝트에서 기본으로 포함되는 dom을 제거
	- 폴리필을 사용하는 프로젝트에서 ECMA스크립트 특정 버전을 포함할 때 사용
- lib 옵션은 내장된 언어 API를 나타내는데 사용하고 target 옵션은 존재하는 구문 기능을 나타내는 것
