
## 배열 타입

- **초기 배열에 담긴 요소를 통해 타입을 유추**하고 **배열이 해당 데이터 타입에서만 작동하도록 제한**한다.
    
    ```tsx
    const warriors = ["Artemisia", "Boudica"];
    
    warriors.push("Zenobia"); // string 타입이므로 ok
    
    warriors.push(true);
    // Error: Argument of type boolean is not assignable to parameter of type string
    ```
    
- 초기값 없이 타입 애너테이션을 지정해두면 나중에 배열 값을 받을 수 있다.
    
    ```tsx
    let arrayOfNumbers: number[]; // Array<number>과 동일한 구문
    
    arrayOfNumbers = [4, 8, 15, 16, 23, 42];
    ```

### 배열과 함수 타입

```tsx
let createStrings: () => string[]; // string 타입을 반환하는 함수

let stringCreators: (() => string)[]; // 각각 string을 반환하는 함수 배열
```

### 유니언 타입 배열

```tsx
// string 또는 number의 배열
let stringOrArrayOfNumbers: string | number[];

// 각각 number 또는 string인 요소의 배열
let arrayOfStringOrNumbers: (string | number)[];
```

타입스크립트는 **배열의 선언에서 두 가지 이상의 요소 타입이 포함되는 경우 유니언 타입 배열**임을 알게 된다. **즉, 배열의 요소 타입은 배열에 담긴 모든 요소에 대한 모든 가능한 타입의 집합**이다.

```tsx
const namesMaybe = [ // (string | undefined)[]
	"a",
	"b",
	undefined
];
```

### any 배열의 진화

- 초기에 빈 배열로 설정된 변수에서 타입 애너테이션을 포함하지 않으면 타입스크립트는 배열을 **any\[]로 취급**한다.
- **타입 애너테이션이 없는 빈 배열은 잠재적으로 잘못된 값 추가를 허용**해 타입스크립트의 타입 검사기가 갖는 이점을 부분적으로 무력화한다.

```tsx
let values = []; // any[]

values.push(""); // string[]

values[0] = 0; // (number | string)[]
```

### 다차원 배열

- 다차원 배열은 원래의 타입을 가지며 끝에 \[ ]가 있고 그 뒤에 \[ ]를 추가한다고 생각하면 쉽다.

```tsx
let arrayOfArraysOfNumbers: (number[])[]; // number[][] 타입
```


## 배열 멤버

- 배열 타입이 string\[] 타입이므로 배열 멤버는 string 타입이다.

```tsx
const defenders = ["a", "b"];

const defender = defenders[0]; // 타입 string
```

- 유니언 타입 배열의 멤버는 그 자체로 동일한 유니언 타입이다.

```tsx
const soldierOrDates = ["a", new Date(2000,1,1)];

const soldierOrDate = soldierOrDates[0]; // string | Date 타입
```

### 주의 사항: 불안정한 멤버

- 타입 시스템은 때로는 값 타입에 대한 타입 시스템의 이해가 올바르지 않을 수 있다. 특히 배열은 타입 시스템에서 불안정한 소스이다.
- 타입스크립트는 **검색된 배열의 멤버가 존재하는지 의도적으로 확인하지 않고 undefined가 아닌 해당 배열의 멤버를 반환한다고 가정**한다.

```tsx
function withElements(elements: string[]) {
	console.log(elements[9001].length); // 타입 오류 없음
}

withElements(["a", "b"]);
```

- `noUncheckedIndexedAccess` 플래그가 있지만 이 플래그는 매우 엄격해서 대부분의 프로젝트에서 사용하지 않는다.


## 스프레드와 나머지 매개변수

### 스프레드

- 동일한 타입의 배열을 결합하면 출력 배열도 동일한 타입이다.
- 서로 다른 타입의 배열을 결합하면 원래의 타입 중 어느 하나의 요소인 유니언 타입 배열로 이해된다.

```tsx
const soldiers = ["a", "b", "c"]; // string[]

const soldierAges = [90, 19, 45]; // number[]

const conjoined = [...soldiers, ...soldierAges]; // (string | number)[]
```

### 나머지 매개변수 스프레드

- 나머지 매개변수를 위한 인수로 사용되는 배열은 나머지 매개변수와 동일한 배열 타입을 가져야 한다.

```tsx
function logWarriors(greeting: string, ...names: string[]) { /** ... */ }

const warriors = ["a", "b", "c"];

logWarriors("hello", ...warriors);

const birthYears = [1900, 1901, 1902];

logWarriors("born in", ...birthYear);
// Error: arguments of type number is not assignable to parameter of type string
```


## 튜플

- 고정된 크기의 배열로 각 인덱스에 알려진 특정 타입을 갖는다.
- 배열의 모든 가능한 멤버를 갖는 유니언 타입보다 더 구체적이다.
- 다음 yearAndWarrior는 인덱스 0에 number타입, 인덱스 1에 string 타입을 갖는 튜플 타입이다.

```tsx
let yearAndWarrior: [number, string];

yearAndWarrior = [530, "a"]; // ok

yearAndWarrior = [false, "a"];
// Error: type boolean is not assignable to type number

yearAndWarrior = [530];
// Error: type [number] is not assignable to type [number, string]
```

### 튜플 할당 가능성

- 튜플 타입은 가변 길이의 배열 타입보다 더 구체적으로 처리된다. 즉, 가변 길이의 배열 타입은 튜플 타입에 할당할 수 없다.
    - 다음 예에서 pairLoose가 \[boolean, number] 튜플로 선언되었다면 할당이 가능했을 것
    
    ```tsx
    const pairLoose = [false, 123]; // (boolean | number)[]
    
    const pairTupleLoose: [boolean, number] = pairLoose;
    // Error: type (number | boolean)[] is not assignable to type [boolean, number]
    ```
    
- 길이가 다른 튜플은 서로 할당할 수 없다.
    
    ```tsx
    const tupleThree: [boolean, number, string] = [false, 1234, "a"];
    
    const tupleTwoExact: [boolean, number] = [tupleThree[0], tupleThree[1]];
    
    const tupleTwoExtra: [boolean, number] = tupleThree;
    // Error: type [boolean, number, string] is not assignable to type [boolean, number]
    ```
    
- 함수에 전달할 인수를 저장하는 데 특히 유용하다. 스프레드 나머지 매개변수로 전달된 튜플에 정확한 타입 검사를 제공할 수 있다.
    - logPair 함수의 인수로 `(string | number)[]` 타입의 값을 전달하려고 하면 타입의 안전을 보장할 수 없다.
    - `[string, number]` 튜플의 값이면 타입이 일치함을 보장할 수 있다.
    
    ```tsx
    function logPair(name: string, value: number) { /** ... */ }
    
    const pairArray = ["a", 1];
    logPair(...pairArray);
    // Error: a spread argument must either have a tuple type or be passed to a rest parameter
    
    const pairTupleIncorrect: [number, string] = [1, "a"];
    logPair(...pairTupleIncorrect);
    // Error: argument of type number is not assignable to parameter of type string
    
    const pairTupleCorrect: [string, number] = ["a", 1];
    logPair(...pairTupleCorrect); // ok
    ```

### 튜플 추론

- 타입스크립트는 **생성된 배열을 튜플이 아닌 가변 길이의 배열로 취급**한다.
    
    ```tsx
    // 반환 타입은 [string, number] 튜플 타입이 아니라 (string | number)[]로 유추된다.
    function firstCharAndSize(input: string) {
    	return [input[0], input.length];
    }
    
    // firstChar: string | number
    // size: string | number
    const [firstChar, size] = firstCharAndSize("Gudit");
    ```
    
튜플 타입임을 나타내는 방법

1. **명시적 튜플 타입 (타입 애너테이션)**
    
    ```tsx
    // 반환 타입: [string, number]
    function firstCharAndSizeExplicit(input: string): [string, number] {
    	return [input[0], input.length];
    }
    
    // firstChar 타입: string
    // size 타입: number
    const [firstChar, size] = firstCharAndSizeExplicit("aaaaa");
    ```
    
2. **const 어서션**

- 타입 애너테이션은 코드 변경에 따라 작성 및 수정이 필요하다. 대안으로 const 어서션을 사용할 수 있다.
- `as const` 연산자 사용

	```tsx
	const unionArray = [1157, "a"]; // (string | number)[]
	        
	const readonlyTuple = [1157, "a"] as const; // readonly [1157, "a"]
	```

- 튜플로 전환하는 것을 넘어 **튜플이 읽기 전용이고 값을 수정할 수 없음을 나타낼 수 있다.**

	```tsx
	const pairMutable: [number, string] = [1157, "a"];
	pairMutable[0] = 1247; // ok
	
	const pairAlsoMutable: [number, string] = [1157, "a"] as const;
	// Error: type 'readonly [1157, "a"]' is 'readonly'
	// and cannot assigned to the mutable type '[number, string]'
	        
	const pairConst = [1157, "a"] as const;
	pairConst[0] = 1247;
	// Error: cannot assign to  '0' because it is a read-only property
	```

- **함수 반환에 편리하다.**
 
	```tsx
	// 반환 타입: readonly [string, number]
	function firstCharAndSizeExplicit(input: string) {
		return [input[0], input.length] as const;
	}
	        
	// firstChar 타입: string
	// size 타입: number
	const [firstChar, size] = firstCharAndSizeExplicit("aaaaa");
	```
