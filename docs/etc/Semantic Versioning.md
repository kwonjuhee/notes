## Semantic Versioning

> 패키지 릴리즈 버전 관리 규칙

- major, minor, patch 세 가지 숫자를 조합해서 버전을 관리한다. `MAJOR.MINOR.PATCH`
- 패키지 버전은 `1.0.0`부터 시작하고 각 버전이 증가하는 기준은 다음과 같다.
  - `major` : 하위호환이 되지 않는 api 변경 사항들
  - `minor` : 하위호환이 되는 범위 내에서 기능 추가 및 deprecate, 개선사항
  - `patch` : 하위호환이 되는 범위 내에서 버그 픽스
- major 버전을 올릴 때 minor와 patch 버전은 0으로 초기화 / minor 버전을 올릴 때 patch 버전은 0으로 초기화
- major 버전이 0(0.y.z)인 경우 초기 개발을 위한 것

### 💡 사용 이유

- 숫자를 통해 변경 사항의 정도를 전달/이해할 수 있으며 필요한 경우 코드를 조정할 수 있다.
- dependency hell 개선
  - 의존성을 너무 엄격하게 관리하면 버전에 갇히게 될 위험이 있다. 
  - 의존성을 너무 느슨하게 관리하면 버전이 엉킬 수 있다.

### 허용하는 버전 범위 명시

- patch releases: `1.0` or `1.0.x` or `~1.0.4`
- minor releases: `1` or `1.x` or `^1.0.4`
- major releases: `*` or `x`

**틸드(~)**

- 마이너 버전이 명시되어 있으면 패치 버전을 업데이트
- `~1.0.4` : `>= 1.0.4`, `< 1.1.0`

**캐럿(^)**

- 마이너 버전과 패치 버전을 업데이트
- 하위호환 보장
- `^1.0.4` : `>= 1.0.4`, `< 2.0.0`

### pre-release

- 대시(-)를 붙이고 마침표(.)로 구분된 식별자를 더해서 정식 배포를 앞둔 (pre-release) 버전을 표기할 수 있다.
- 식별자들은 아스키 문자, 숫자, 대시로만 구성한다.
  - `1.0.0-alpha`, `1.0.0-alpha.1`, `1.0.0-0.3.7`, `1.0.0-x.7.z.92`
- pre-release 버전은 연관된 일반 버전보다 우선순위가 낮다. (`1.0.0-alpha < 1.0.0`)
- 불안정하며 호환성 요구사항이 충족되지 않을 수 있다.

### 빌드 메타데이터

- 빌드 메타데이터는 + 기호를 붙인 뒤에 마침표로 구분된 식별자를 더해서 표현한다.
- 빌드 메타데이터는 버전 간의 우선순위를 판단할 때 무시된다.
- 빌드 메타데이터만 다른 두 버전의 우선순위는 같다.
- `1.0.0-alpha+001`, `1.0.0+20130313144700`, `1.0.0-beta+exp.sha.5114f85`
