# 문자열 인코딩 방식

## ASCII *(American Standard Code for Information Interchange)*

- 7bit로 하나의 문자를 표현하기 때문에 총 128개의 문자를 표현할 수 있다.
- 영문 알파벳을 위한 인코딩 방식으로 다른 언어는 표현이 불가능하다.

## ANSI *(American National Standard Institute)*

- 7bit는 ascii와 동일하고 1bit로 CodePage를 표현한다. CodePage는 특정 언어를 위한 코드 표를 말한다.
- 영어가 아닌 다른 언어들을 사용하는 환경에서는 호환성이 떨어진다.

## EUC-KR *(Extended Unix Code-Korea)*

- 한글 지원을 위해 유닉스 계열에서 등장한 완성형 인코딩 방식
    - 완성형이란 완성된 각 문자에 코드를 부여하는 방식
    - 조합형이란 문자를 이루는 각 요소 (초성, 중성, 종성)에 코드를 부여하는 방식
- 2byte로 하나의 문자를 표현한다.
- 128까지는 KS X 1003 체계, 나머지 중 일부는 KS X 1001 체계와 동일하다. KS X 1001 체계는 한글 단어를 2350자만 사전순으로 나열했기 때문에 모든 단어를 표현하기에는 부족하다.

## CP949

- EUC-KR을 보완하기 위해 등장한 확장 완성형 인코딩 방식
- EUC-KR이 사용하지 않는 나머지 바이트열을 활용하여 대부분의 한글 단어를 표현할 수 있도록 개선 및 확장
- EUC-KR에서 확장된 한글 단어들의 경우 사전순으로 배열하지 않았다.
- 마이크로소프트에서 만들었기 때문에 MS949라고도 한다.

## 유니코드 (Unicode)

- 전 세계에서 사용하는 수많은 문자들에 각각 부여한 코드들의 집합
- 전 세계의 기기들이 통일된 인코딩 방식을 사용하기 위해 고안됨
- `U+XXXX` 의 형태로 표현
- UTF-N은 유니코드 기반의 문자들을 바이트열에 인코딩하는 방식을 의미한다.
    - 유니코드는 문자-코드 매핑 표!

## UTF-N

- 유니코드 기반의 문자들을 바이트열에 표현하는 인코딩 방식
- 유니코드를 각 인코딩 방식에서 정해둔 규칙에 따라 변형시켜서 바이트열에 표현한다. (ASCII, ANSI처럼 그대로 표현❌)

> **UTF-8 방식**
> 인코딩하려는 문자의 코드가 속한 범위에 따라 1byte ~ 4byte로 인코딩하는 가변 길이 인코딩 방식

# URL Encoding이 필요한 이유

- 인터넷을 통해 전송할 수 있는 문자는 오로지 ASCII 문자이다.
- ASCII 문자라고 하더라도 예약된 의미를 가지고 있는 문자의 경우 이스케이프 처리가 필요하다. `/, &, =, 공백문자 등등`

> [!note]
> 
> 🔥 따라서 URL에서 **URL로 사용할 수 없는 문자** 혹은 **URL로 사용할 수 있지만 의미가 왜곡될 수 있는 문자**들을 `%XX`의 형태로 변환하는 인코딩 과정이 필요하다. 이를 원래의 형태로 되돌리는 것은 디코딩이라고 함


# JavaScript 빌트인 함수

**encodeURI / decodeURI**

- 완전한 URI를 문자열로 전달받아 인코딩/디코딩한다.
- UTF-8 방식을 따라 한글 문자 1개는 3바이트로 인코딩된다.

**encodeURIComponent / decodeURIComponent**

- URI의 구성요소를 인코딩/디코딩한다.
- `알파벳, 숫자 0 ~ 9,- _ . ! ~ * ‘ ( ) 문자`는 이스케이프 처리에서 제외된다.

⚠️ 전자 방식은 전달된 문자열을 완전한 URI 전체라고 간주하여 쿼리스트링 구분자로 사용되는 `=, ?, &`는 인코딩하지 않는다.

⚠️ 후자 방식은 전달된 문자열을 쿼리 스트링의 일부로 간주하여 `=, ?, &`까지 인코딩한다.
