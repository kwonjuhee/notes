다른 출처(cross-origin)의 리소스를 사용할때 CORS의 동작 방식을 제어하는 속성으로 audio, img, link, script, video 요소에서 사용된다.

- `anonymous` : credentials flag가 same-origin으로 설정되며 목적지가 동일 출처가 아닌 이상 리소스 요청에 인증 정보(쿠키, 클라이언트측 TLS 인증서, HTTP 인증)를 포함하지 않는다. 
- `use-credentials` : credentials flag가 `'include'`로 설정되고 리소스 요청에 유저 인증 정보가 항상 포함된다.
- `""` 또는 empty 값: `anonymous`와 동일

### 동일 출처 정책에서 '외부 출처'의 접근을 허용하는 경우

무조건 외부 출처의 리소스를 제한하는 것은 아니고 제한적으로 외부 출처를 허용한다. 대표적으로 현재의 웹 페이지에 단순 삽입(embed)되는 경우!

- `<script src="…"></script>`로 단순히 읽기 전용 스크립트 파일 삽입
- `<link rel="stylesheet" href="…">`로 '외부 CSS 파일 연결
- `<video>`와 `<audio>`로 재생하는 미디어
- `<img>`, `<picture>`로 표시되는 이미지
- `<iframe>`으로 삽입되는 것
- `<object>`, `<embed>`로 삽입되는 외부 리소스
- `@font-face`로 적용되는 글꼴(일부 브라우저에서는 동일 출처를 요구할 수 있음)

### 동일 출처 정책에서 '외부 출처'의 접근을 제한하는 경우

단순히 외부 출처의 리소스를 삽입하는 경우가 아니라 현재의 웹페이지가 외부 출처의 리소스와 상호작용 하는 경우에는 접근을 제한한다.

- **데이터 통신:** 현재의 웹페이지가 '외부 출처'의 리소스의 데이터와 통신하는 경우 (예: AJAX 요청을 통한 데이터 가져오기)
- **쿠키 및 저장 정보 접근:** '외부 출처'의 리소스가 현재 웹페이지 정보에 접근을 시도할 경우 (예: 사용자의 쿠키에 접근을 시도)
- **단순 삽입된 '외부 출처 리소스' 내의 외부 출처 리소스:** 단순 삽입된 '외부 출처 리소스' 내의 외부 출처 리소스가 있을 경우 보안을 유지하기 위해 해당 접근이 제한될 수 있습니다.
- **스크립트 실행:** '외부 출처' 리소스의 스크립트를 현재 웹 페이지에서 실행하려는 경우나 '외부 출처' 리소스가 현재 웹 페이지의 스크립트 API를 호출하려는 경우 (일부 특정 API는 허용될 수 있습니다.)

### font 파일인 경우 주의할 점

링크된 리소스가 폰트 파일인 경우에는 동일 출처라 하더라도 다양한 이유로 인해 익명 모드 CORS를 사용하여 가져와야 한다.

일반적인 리소스와 달리, 웹 폰트는 `@font-face` 규칙을 사용하여 웹 페이지에 삽입되는데, 이 과정에서 브라우저는 백그라운드에서 일부 CORS 요청을 트리거할 수 있다. 따라서 `crossorigin` 속성을 `anonymous`로 사용하여 실제 폰트 로딩 간의 CORS 모드 일치를 보장하는 것이 좋다.
