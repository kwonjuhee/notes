## HTTP (HyperText Transfer Protocol)

- 인터넷에서 데이터를 주고받을 때 사용되는 프로토콜(=약속)
- 웹에서 이루어지는 모든 데이터 교환의 기초
- 클라이언트와 서버간 통신 프로토콜
   - 클라이언트: 리소스를 요청하는 쪽
   - 서버: 리소스를 제공하는 쪽
   - 요청과 응답을 교환하여 성립
- 신뢰 가능한 전송 프로토콜이라면 이론상으로 무엇이든 사용할 수 있으나 보통 TCP 위에서 동작
  - HTTPS는 TLS 위에서 동작
  - HTTP/3부터는 UDP 사용

### 단방향성

- 클라이언트로부터 요청을 보내면 서버가 응답한다.
- 반드시 클라이언트 측으로부터 통신이 시작된다.

### 비연결성 (connectionless)

- 클라이언트 요청에 대해 서버가 응답을 마치면 연결을 끊어버린다.
- 🟢TCP 연결은 기본적으로 유지되기 때문에 서버 자원 낭비를 막기 위해 연결 종료
   - 웹 사이트 요청시 HTML, JS, CSS, 이미지 등 수많은 자원이 로드됨
- 🔴매번 모든 요청에 대해 TCP 연결 및 해제 과정을 거치므로 네트워크 비용 측면에서 비효율적
   - HTTP 1.1부터 TCP 연결을 유지하는 지속 연결(Persistent Connection)이 디폴트 (Connection: Keep-alive)

### 무상태성 (stateless)

- 요청과 응답을 교환하는 동안 상태를 저장하지 않는다.
- 🟢scalability를 확보하여 많은 데이터를 빠르고 확실하게 처리할 수 있도록 간단하게 설계되어 있는 것
- 🔴웹이 진화함에 따라 상태 유지의 필요가 생김 (ex. 로그인 정보) => 쿠키 기술이 도입됨

## HTTP 메시지

- HTTP에서 서버와 클라이언트 간에 교환되는 정보로 요청(request)과 응답(response) 타입이 있다.
- ASCII로 인코딩된 텍스트 정보
- 메시지 구조는 head(시작줄 + HTTP헤더)와 body(payload)로 구성된다.

## HTTP 요청 메서드

- 클라이언트가 요청을 보낼 때 HTTP 요청 메서드를 통해 리소스에 어떠한 행동을 원하는지 명시한다.
- CRUD - POST/GET/PUT/DELETE

**`GET`** : URL(URI)로 식별된 리소스 조회

- 전달하고 싶은 정보는 쿼리를 통해서 전달한다. (쿼리스트링, 쿼리파라미터)
- 메시지 바디를 통해서 전달할 수는 있지만 지원하지 않는 경우가 많아 권장되지 않는다.
- JSON으로 데이터를 넘길 때 GET 메서드 사용이 어려운 경우 POST를 사용하기도 한다.

**`POST`** : 정보 전송, 주로 리소스 생성에 사용

- 메시지 바디를 통해 데이터를 전달한다.
- 서버 상태의 변화나 부수효과를 일으킨다.
- location은 자원이 새로 생성된 URI 경로를 의미

**`PUT`** : 리소스 대체

- 리소스가 없으면 생성한다.
- ⚠️요청한 payload로 완전히 대체되기 때문에 리소스의 일부만 전달할 경우 나머지 속성은 삭제된다.
- vs POST: 리소스 위치 지정 / 지정X
- vs PATCH: 완전히 변경 / 일부만 변경

**`PATCH`** : 리소스의 일부만을 수정

**`DELETE`** : 특정 리소스 삭제

**`HEAD`** : GET메서드와 동일하지만 응답 바디 포함 X

- 리소스를 조회하지 않고 확인만 하는 용도
- 메시지 헤더를 통해 URI 유효성과 리소스 갱신 시간을 확인하는 데에 사용할 수 있다.

**`OPTIONS`** : 지원 가능한 메서드 문의

- preflight 요청에 사용되어 CORS 정책 검사    

## HTTP 상태 코드

- 서버는 요청에 대한 처리 결과를 상태코드로 반환한다.
- 3자리 숫자와 설명으로 구성된다.

| 상태 코드 | 설명 |
| --- | --- |
| 1xx informational | 요청을 받고 처리중 |
| 2xx Success | 요청이 정상적으로 처리되었음 |
| 3xx Redirection | 요청을 완료하기 위해서 추가 작업이 필요함 |
| 4xx Client Error | 요청이 잘못되었음 |
| 5xx Server Error | 서버에서 요청 처리를 실패했음 |
