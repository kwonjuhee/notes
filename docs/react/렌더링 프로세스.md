### 1. hook을 통해 컴포넌트 state 업데이트

- hook의 구현체에서 반환하는 상태 변경 함수(dispatchAction)를 호출하면 hook 객체의 queue에 업데이트 객체를 연결리스트로 추가
- 컴포넌트에 적용된 상태 값과 업데이트 값을 비교해서 변경되지 않았다면 스케줄링하지 않고 중단하는 식으로 최적

### 2. 업데이트를 반영할 Work를 스케줄링

### 3. Render phase - Work를 통해 VDOM 재조정 작업 진행

1. root부터 업데이트 컴포넌트까지 current를 복제하여 workInProgress 트리 구축
	- 업데이트 컴포넌트의 서브 트리를 제외한 부분은 변경된 부분이 없으므로 굳이 fiber를 새로 만들 필요가 없다.
	- 따라서 current를 재사용하여 workInProgress를 만든다.
2. 컴포넌트의 state, props 변경을 확인하여 컴포넌트 호출 여부를 판단
	- 업데이트되지 않았다면 라이프사이클 hook의 잔여물을 fiber에서 제거하고 work를 끊어준다. (bailoutOnAlreadyFinishedWork)
	- 만약 자손에서 업데이트 컴포넌트가 있다면 자식 WIP가 반환되어 계속해서 밑으로 work가 진행될 것이지만 없다면 여기서 work는 종료된다.
3. 업데이트 컴포넌트를 호출하여 변경된 상태 값을 반영한 자식 React element를 만든다.
4. 이를 fiber로 확장하여 재조정 작업을 진행한다.
	- fiber란 VDOM 노드이며 컴포넌트의 모든 정보를 관리한다.
	- React element와 current fiber를 비교하여 workInProgress를 새로 만들어야 하는지, 아니면 어떤 부분들이 변경되었는지, current는 삭제되어야 하는지 등 두 컴포넌트를 비교하여 "재조정"하는 작업을 말한다.
	- fiber에 side effect를 나타내는 tag를 비트마스킹한다. side effect란 트리에 변경점을 불러오는 모든 행위를 말하며 commit phase에서 해당 tag를 기반으로 마무리(DOM 조작, 라이프사이클 실행)를 한다.
6. 위 과정을 leaf 노드까지 반복하여 WIP 트리를 완성한다.
7. 재조정 작업으로 얻은 fiber를 commit phase에서 사용할 수 있도록 준비하고 work를 마무리한다. (completeWork)
	- fiber를 DOM에 올리기 위한 사전 작업으로 생각할 수 있으며 fiber와 대응하는 HTML element 생성, 수정, 삭제, 이벤트 핸들러 바인딩 등 Work를 통해 발생한 모든 결과물을 처리한다. 새로 생성된 fiber라면 element 역시 새로 만들어야 하고 그렇지 않다면 current와 WIP이 가지고 있는 props의 차이점을 찾아내어 기존 element에 적용한다.
	- leaf 노드의 work를 마무리하고 형제 노드 -> 부모 노드 순으로 마무리해나가다 root에 도달하며 끝난다.
	- 이때, effect를 위로 엮어준다. 최종적으로 host root는 side effect가 발생한 fiber들이 모두 엮여있는 리스트의 head를 가지고 있게 된다.


render phase에서 업데이트가 발생한다면 이미 work가 진행중이므로 work를 스케줄링하거나 성능 최적화를 위한 처리가 필요 없다. 단지 render phase update가 더 이상 발생하지 않을 때까지 계속 컴포넌트를 재호출하여 업데이트를 소비

### 4. Commit phase - Work를 진행하며 발생한 변경점 적용

commit phase에는 소비 시점이 effect의 성격에 따라 DOM에 변형을 가하는 시점과 그 전, 후로 나뉘어진다.

전

- 클래스 컴포넌트: getSnapshotBeforeUpdate
- 함수형 컴포넌트: clean-up-useEffect, useEffect
- 호스트 컴포넌트: X

변형

- 클래스 컴포넌트: componentWillUnmount
- 함수형 컴포넌트: clean-up-useLayoutEffect, clean-up-useEffect
- 호스트 컴포넌트: element 삽입, 수정, 삭제

후

- 클래스 컴포넌트: componentDidMount, componentDidUpdate
- 함수형 컴포넌트: useLayoutEffect
- 호스트 컴포넌트: auto-focus

위 작업은 useEffect를 제외하고는 모두 동기적으로 처리된다. DOM 변경과 화면 렌더링 사이 또는 렌더링 이후 개발자가 개입할 수 있게 해준다.
