

## 2.1 타입의 종류

- 타입이란 자바스크립트에서 다루는 **값의 형태**에 대한 설명
- 여기서 형태란 값에 존재하는 속성과 메서드, 그리고 typeof 연산자가 설명하는 것을 의미한다.
- 가장 기본적인 타입은 원시 타입(primitive type) 7가지와 동일
    - null / undefined / boolean / string / number / bigint / symbol
- 타입스크립트는 계산된 초기값을 갖는 변수의 타입을 유추할 수 있다.

### 타입 시스템

> 타입 시스템은 프로그래밍 언어가 프로그램에서 가질 수 있는 타입을 이해하는 방법에 대한 규칙 집합

타입스크립트의 타입 시스템은 다음과 같이 작동한다.

1. 코드를 읽고 존재하는 모든 타입과 값을 이해한다.
2. 각 값이 초기 선언에서 가질 수 있는 타입을 확인한다.
3. 각 값이 추후 코드에서 어떻게 사용될 수 있는지 모든 방법을 확인한다.
4. 값의 사용법이 타입과 일치하지 않으면 사용자에게 오류를 표시한다.

아래 예시에서 동작 순서

```tsx
let firstName = "Whitney";
firstName.length();
// Error: This expression is not callable.
// Type 'Number' has no call signatures.
```

1. 코드를 읽고 firstName이라는 변수를 이해한다.
2. 초깃값이 “Whitney”이므로 firstName이 string 타입이라고 결론짓는다.
3. firstName의 `length` 멤버를 함수처럼 호출하는 코드를 확인한다.
4. string의 `length` 멤버는 함수가 아닌 숫자라는 오류를 표시한다. 즉, 함수처럼 호출할 수 없다.

### 오류 종류

1. **구문 오류** : 타입스크립트가 코드로 이해할 수 없는 잘못된 구문을 감지할 때 발생

	- 자바스크립트로 변환될 수 없도록 차단한다. 
		- 컴파일러 버전과 설정에 따라 다름
		- 기본 tsc 설정에서는 가능
	- let let wat; -> let let, wat;

2. **타입 오류** : 타입스크립트의 타입 검사기가 프로그램 타입에서 오류를 감지했을 때 발생

	- 구문상 유효하지만 실행시 오류 발생 가능성이 있음
	- 자바스크립트로 변환되는 것을 차단하지는 않는다.


## 2.2 할당 가능성

- 타입스크립트는 **변수의 초기값을 읽고 해당 변수의 타입을 결정**한다. 나중에 새로운 값이 할당되면 **할당된 값의 타입이 변수의 타입과 동일한지 확인**한다.
- 함수 호출이나 변수에 값을 제공할 수 있는지 여부를 확인하는 것을 **할당 가능성**이라고 한다. 즉, 전달된 값이 예상된 타입으로 할당 가능한지 여부를 확인
- `Type A is not assignable to type B`의 오류 형태
	- A는 할당하려고 시도하는 값, B는 값이 할당되는 변수

## 2.3 타입 애너테이션

변수에 초기값이 없는 경우 변수를 암묵적으로 any 타입으로 간주한다. 이러한 변수를 **진화하는 any**라고 하는데, 이 변수에는 특정 타입을 강제하는 대신 새로운 값이 할당될 때마다 변수 타입에 대한 이해를 발전시킨다. 

이렇게 진화하는 any를 허용하게 되면 타입스크립트의 타입 검사 기능을 잘 활용할 수 없다. 검사를 위해 알려진 타입이 없기 때문. 타입스크립트는 값이 어떤 타입인지 알고 있을 때 가장 잘 작동한다.

```tsx
let rocker; // any

rocker = "aaa"; // string
rocker.toUpperCase(); // ok

rocker = 123; // number
rocker.toPrecision(1); // ok

rocker.toUpperCase(); // Error
```

타입스크립트는 초기값을 할당하지 않고도 변수의 타입을 선언할 수 있는 **타입 애너테이션 (type annotation)** 을 제공한다.

```tsx
let rocker: string;

// 타입 애너테이션으로 정의한 타입 외의 값을 할당하면 오류 발생
rocker = 1; // Error
```

이러한 타입 애너테이션은 자바스크립트로 컴파일하면 삭제되기 때문에 런타임 코드에 영향을 주지 않는다.

> ⚠️ 타입 애너테이션은 타입스크립트가 자체적으로 수집할 수 없는 정보를 타입스크립트에 제공하는 목적이다. 타입을 유추할 수 있는 변수에 타입 애너테이션을 다는 것은 중복이다. 유추되지 않은 정보를 명시적으로 알려줘야 하는 상황에서만 사용하는 것이 좋다.
> 
> 코드를 명확하게 문서화하거나 실수로 변수 타입이 변경되지 않도록 타입스크립트를 보호하기 위해 사용하는 것이 경우에 따라서 유용할 수도 있다.


## 타입 형태

타입스크립트는 단순히 타입을 확인할 뿐만 아니라 **접근하려는 속성이 해당 변수 타입에 존재하는지 확인**하기도 한다.

```ts
let rapper = "~~~";
rapper.length; // ok

rapper.push(); // Error: Property 'push' does not exist on type 'string'.
```

객체 타입인 경우

```ts
let cher = {
  firstName: "",
  lastName: "",
}

cher.middleName;
// Error: Property 'middleName' does not exist on type '{ firstName: string; lastName: string; }'.
```

타입스크립트가 객체의 형태에 대한 이해를 바탕으로 할당 가능성뿐만 아니라 객체 사용과 관련된 문제도 알려주는 것

### 모듈에서 주의할 점

- 타입스크립트는 export 또는 import가 없는 파일을 전역 스코프로 간주한다. 따라서 동일한 이름의 변수가 충돌할 수도 있다.
	- 문제를 해결하기 위해 `export {}`를 추가하여 강제로 모듈이 되도록 만들 수 있다.
- 타입스크립트는 CJS와 같은 이전 모듈 시스템의 import, export 형태를 인식하지 못한다. 따라서 일반적으로 `require` 함수에서 반환된 값을 any 타입으로 인식한다.
