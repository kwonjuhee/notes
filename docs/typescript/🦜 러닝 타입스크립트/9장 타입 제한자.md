
## top 타입

- 시스템에서 가능한 모든 값을 나타내는 타입
- 모든 타입은 top 타입에 할당할 수 있다.

### any 다시 보기

- 모든 타입의 위치에 제공될 수 있다는 점에서 top 타입처럼 작동할 수 있다.
- 일반적으로 console.log의 매개변수와 같이 모든 타입의 데이터를 받아들이는 위치에서 사용한다.
- 타입 검사를 수행하지 않으므로 안정성이 부족하다는 문제가 있다.

```tsx
function greetComedian(name: any) {
  // 타입 오류 없음
  console.log(name.toUpperCase());
}

greetComedian({ name: "a" }} // Runtime error
```

- 어떤 값이든 될 수 있음을 나타내려면 unknown 타입이 훨씬 안전하다.

### unknown

- 진정한 top 타입
- 모든 객체를 unknown 타입의 위치로 전달할 수 있다는 점에서 any 타입과 유사하지만 타입스크립트는 unknown 타입의 값을 훨씬 더 제한적으로 취급한다.
    - unknown 타입 값의 속성에 직접 접근할 수 없다.
    - unknown 타입은 top 타입이 아닌 타입에는 할당할 수 없다.
- **`instanceof`, `typeof`, `타입 어서션`을 사용하여 값의 타입이 제한된 경우에 unknown 타입 속성에 접근이 가능**하다.

```tsx
// unknown 타입 값의 속성에 직접 접근할 수 없다.
function greetComedian(name: unknown) {
  console.log(name.toUpperCase());
  // Error: Object is of type 'unknown'
}

// 타입을 제한하면 가능
function greetComedian(name: unknown) {
  if (typeof value === "string") {
    console.log(name.toUpperCase()); // ok
  }
}
```


## 타입 서술어 (type predicate)

- 인수가 특정 타입인지 여부를 나타내기위해 boolean 값을 반환하는 함수를 위한 특별한 구문을 타입 서술어(type predicate) 또는 **사용자 정의 타입 가드(user-defined type guard)** 라고 한다.
    - `function typePredicate(input: WideType): input is NarrowType;`

- instanceof 또는 typeof와 유사한 **자체 타입 가드를 생성**한다. 타입 서술어는 일반적으로 **매개변수로 전달된 인수가 매개변수의 타입보다 더 구체적인 타입인지 여부를 나타내는 데 사용**된다.

- **타입을 좁히는 로직을 함수로 감싸는 경우 타입을 좁힐 수 없기 때문에 사용**
    - 다음 예제에서 value의 타입이 좁혀지지 않는다.
    - 타입스크립트는 isNumberOrString(value)가 boolean 값을 반환한다는 사실만을 알 수 있고 인수의 타입을 좁히기 위함이라는 건 알 수 없다.
    
    ```tsx
    function isNumberOrString(value: unknown) {
      return ["number", "string"].includes(typeof value);
    }
    
    function logValueIfExists(value: number | string | null | undefined) {
      if (isNumberOrString(value)) {
        // value: number | string | null | undefined 타입
        value.toString();
        // Error: Object is possibly undefined
      }
      else {
        console.log("Value does not exist:", value);
      }
    }
    
    ```
    
 - 타입 서술어의 반환타입을 명시적으로 변경(`value is number | string`)하면 value가 number | string 타입인 경우 해당 코드 블록의 value는 number | string 타입을 가져야 한다고 추론한다. 아닌 경우 null | undefined 타입으로 추론한다. 

    ```tsx
    function isNumberOrString(value: unknown): value is number | string {
      return ['number', 'string'].includes(tyepof value);
    }
    
    function logValueIfExists(value: number | string | null | undefined) {
      if (isNumberOfString(value)) {
        // value: number | string 의 타입
        value.toString();
      } else {
        // value: null | undefined의 타입
      }
    }
    ```
    
- 단순히 boolean 값을 반환하는게 아니라 인수가 더 구체적인 타입을 나타내는 것을 표현
- 이미 한 인터페이스의 인스턴스로 알려진 객체가 더 구체적인 인터페이스의 인스턴스인지 여부를 검사하는 데 자주 사용된다.
    - 다음 타입 가드는 Comedian이 구체적으로 StandupComedian인지 여부를 확인하는데 사용
    
    ```tsx
    interface Comedian {
      funny: boolean;
    }
    
    interface StandupComedian extends Comedian {
      routine: string;
    }
    
    function isStandupComedian(value: Comedian): value is StandupComedian {
      return "routine" in value;
    }
    
    function workWithComedian(value: Comedian) {
      if (isStandupComedian(value)) {
        // value: StandupComedian 타입
        console.log(value.routine); // ok
      }
      // value: Comedian 타입
      console.log(value.routine);
      // Error: Property 'routine' does not exist on type 'Comedian'
    }
    ```
    
- 타입 서술어는 false 조건에서 타입을 좁히기 때문에 잘못 사용하기 쉽다.
    
    ```tsx
    function isLongString(input: string | undefined): input is string {
      return !!(input && input.length >= 7);
    }
    
    function workWithText(text: string | undefined) {
      if (isLongString(text)) {
        // text: string 타입
        console.log(text.length);
      }
      else {
        // text: undefined 타입
        console.log(text?.length);
        // Error: Property 'length' does not exist on type 'undefined'
      }
    }
    ```


## 타입 연산자

때로는 기존 타입의 속성 일부를 변환해서 두 타입을 결합하는 새로운 타입을 생성해야 할 때도 있다.

### keyof

- 자바스크립트 객체는 일반적으로 string 타입인 동적값을 사용하여 검색된 멤버를 갖는다. 따라서 타입 시스템에서 이러한 키를 표현하려면 상당히 까다로울 수 있다.
    - string 같은 포괄적인 원시 타입을 사용하면 유효하지 않은 키가 허용된다.
    - 다음 예제에서 string 타입의 key는 인터페이스 속성으로 허용되지 않는 값을 허용하고 Ratings는 string 키를 허용하는 인덱스 시그니처를 선언하지 않았기 때문에 에러가 발생한다.
    
    ```tsx
    interface Ratings {
      audience: number;
      critics: number;
    }
    
    function getRating(ratings: Ratings, key: string): number {
      return ratings[key];
      // Error: Element implicitly has an 'any' type because expression of type 'string' can't be used to index type 'Ratings'.
      // No index signature with a parameter of type 'string' was found on type 'Ratings'.
    }
    ```
    
- 허용되는 키를 위한 리터럴 유니언 타입을 사용한다면
    
    ```tsx
    function getRating(ratings: Ratings, key: 'audience' | 'critic'): number {
      return ratings[key]; // Ok
    }
    
    const ratings: Ratings = { audience: 55, critics: 84 };
    
    getRating(ratings, 'audience'); // Ok
    
    getRating(ratings, 'not valid');
    // Error: Argument of type 'not valid' is not assignable to parameter of 'audience' | 'critic'
    ```
    
    - 하지만 인터페이스에 멤버가 많다면 각 멤버의 키를 유니언 타입에 모두 입력하는 것은 번거로운 작업이 될 것

- keyof 연산자 사용하여 **존재하는 타입에 허용되는 모든 키의 유니언 타입을 생성**할 수 있다.
    - 위와 동일한 결과이지만 Ratings 인터페이스가 변경되더라도 수동으로 업데이트할 필요가 없다.
    
    ```tsx
    function getRating(ratings: Ratings, key: keyof Ratings): number {
      return ratings[key]; // Ok
    }
    ```
    

### typeof

- **제공되는 값의 타입을 반환**한다. **값의 타입을 수동으로 작성하는 것이 복잡한 경우에 사용하면 유용**하다.

```tsx
const original = {
  medium: "movie",
  title: "Mean Girls",
};

let adaptation: typeof original;

if (Math.random() > 0.5) {
  adaptation = {...original, medium: "play"}; // Ok
} else {
  adaptation = {...original, medium: 2};
  // Error: type 'number' is not assignable to type 'string'.
}
```

- 타입에 대한 문자열 이름을 반환하는 런타임 연산자인 자바스크립트의 typeof 연산자와는 다르다.

### keyof typeof

- typeof는 값의 타입을 검색하고 keyof는 타입에 허용된 키를 검색한다. 두 키워드를 연결하여 **값의 타입에 허용된 키**를 검색할 수 있다.
- 명시적 인터페이스 타입이 없는 객체에 허용된 키를 나타내는 타입에 대한 코드를 작성하고 업데이트하는 수고를 줄일 수 있다.

```tsx
const ratings = {
  imdb: 8.4,
  metacritic: 82
};

// ratings 값의 키 중 하나를 받는다.
function logRating(key: keyof typeof ratings) { }

logRating("imdb"); // Ok

logRating("invalid");
// Error: Argument of type 'missing' is not assignable to parameter of type 'imdb' | 'metacritic'
```


## 타입 어서션

- 타입스크립트는 코드의 모든 값이 정확히 알려진 타입을 가지는 경우(strongly typed) 가장 잘 작동한다.
- 타입 검사기가 복잡한 코드를 이해할 수 있도록 top 타입과 타입 가드 같은 기능을 제공한다. 하지만 경우에 따라서는 코드가 어떻게 작동하는지 타입 시스템에 100% 정확하게 알리는 것이 불가능할 때도 있다.
    - 예를 들면 `JSON.parse`는 의도적으로 top 타입인 any를 반환한다. 주어진 특정 문자열 값이 특정한 값 타입을 반환해야 한다는 것을 타입 시스템에 안전하게 알릴 수 있는 방법은 없다.
- ✅ 값의 타입에 대한 타입 시스템의 이해를 재정의하기 위한 구문으로 **타입 어서션**을 제공한다. **타입 시스템은 어서션을 따르고 값을 해당 타입으로 처리**한다.
- **가능한 타입 어서션을 사용하지 않는 것이 좋다.** 타입스크립트의 타입 이해를 방해할 수 있기 때문. 최대한 코드가 strongly typed되도록 하는 것이 좋다.

```tsx
const rawData = '["a", "b"]';

JSON.parse(rawData); // any

JSON.parse(rawData) as string[]; // string[]

JSON.parse(rawData) as [string, string]; // [string, string]

JSON.parse(rawData) as ["grace", "frankie"]; // ["grace", "frankie"]
```

### 포착된 오류 타입 어서션

- try 블록의 코드가 예상과는 다른 객체를 예기치 않게 발생할 수 있기 때문에 **catch 블록에서 포착된 오류가 어떤 타입인지 아는 것은 일반적으로 불가능**하다.
- **Error 클래스의 인스턴스를 발생시킬거라 확신한다면 타입 어서션을 사용**
- 발생된 오류가 예상된 오류 타입인지를 확인하기 위해 **instaceof 검사와 같은 타입 내로잉을 사용하는 것이 더 안전**하다.

```tsx
/** 타입 어서션 */
try {
  
} catch(error) {
  console.warn((error as Error).message);
}

/** instanceof */
try {

} catch(error) {
  console.warn(error instanceof Error ? error.message : error);
}
```

### non-null 어서션

- 실제로는 아니지만 이론적으로 null 또는 undefined를 포함할 수 있는 변수에서 null과 undefined를 제거할 때 타입 어서션 사용

```tsx
let maybeDate = Math.random() > 0.5
  ? undefined
  : new Date();

maybeDate as Date; // 타입이 Date라고 간주됨

// non-null 어서션
maybeDate!; // 타입이 Date라고 간주됨
```

- Map.get과 같은 api에서 유용

```tsx
const seasonCounts = new Map([
  ["I Love Lucy", 6],
  ["The Golden Girls", 7],
]);

const maybeValue = seasonCounts.get("I Love Lucy");

console.log(maybeValue.toUpperCase()); // error: object is possibly 'undefined'

const knownValue = seasonCounts.get("I Love Lucy")!;

console.log(knownValue.toUpperCase()); // ok
```

### 타입 어서션 주의 사항

- 꼭 필요한 경우가 아니라면 가능한 사용하지 말자.
- 예를 들어 위의 예제에서 Map이 추후에 다른 값으로 변경된다면? ⇒ non-null 어서션으로 인해 타입스크립트 타임 검사를 통과하지만 런타임 오류가 발생할 수 있다.

### 어서션 vs. 선언

- 타입 선언은 해당 타입 애너테이션에 대한 변수 초기값의 할당 가능성 검사를 수행한다.
- 타입 어서션은 타임 검사 중 일부를 건너뛰도록 명시적으로 지시한다.

```tsx
interface Entertainer {
  acts: string[];
  name: string;
}

// 타입 애너테이션으로 인해 선언된 변수에서 오류를 잡을 수 있다.
const declared: Entertainer = {
  // Error: Property 'acts' is missing
  name: "Moms Mabley",
};

// 오류를 잡을 수 없다. 허용되지만 런타임시 오류가 발생할 수 있다.
const asserted = {
  name: "Moms Mabley",
} as Entertainer;

console.log(asserted.acts.join(", "); // 런타임 에러
```

- 타입 애너테이션을 사용하거나 타입스크립트가 초기값에서 변수 타입을 유추하도록 하는 것이 바람직하다.

### 어서션 할당 가능성

- 타입 중 하나가 다른 타입에 할당 가능한 경우에만 타입 어서션을 허용한다.
- 완전히 서로 관련 없는 두 타입 사이에 타입 어서션이 있는 경우 오류
- 예를 들어 하나의 원시 타입에서 다른 원시 타입으로 전환하는 것은 허용되지 않는다.

```tsx
let myValue = "Stella!" as number; // Error: string 타입은 number 타입으로 변환될 수 없다.
```

## const 어서션

- **배열, 원시 타입, 값, 별칭 등 모든 값을 상수로 취급해야 함을 나타내는데 사용**한다.
- 세가지 규칙 적용
    - 배열은 가변 배열이 아니라 **읽기 전용 튜플로 취급**된다.
    - 리터럴은 일반적인 원시 타입과 동등하지 않고 **리터럴로 취급**된다.
    - **객체의 속성은 읽기 전용으로 간주**된다.

### 원시타입에서 리터럴로

- 리터럴 값을 일반적인 원시 타입으로 확장하기보다 구체적인 리터럴 값을 갖도록 할 때
    
    ```tsx
    const getName = () => "a"; // () => string 타입
    
    const getNameConst = () => "a" as const; // () => "a" 타입
    ```
    
- 값의 특정 필드가 더 구체적인 리터럴 값을 갖도록 할 때
    - 다음 narrowJoke 변수의 style은 string 대신 “one-liner”를 style 값으로 가지므로 Joke 타입이 필요한 위치에 제공될 수 있다.
    
    ```tsx
    interface Joke {
      quote: string;
      style: "story" | "one-liner";
    }
    
    function tellJoke(joke: Joke) {
      if (joke.style === "one-liner") {
        console.log(joke.quote);
      } else {
        console.log(joke.quote.split("\n"));
      }
    }
    
    const narrowJoke = {
      quote: "~~~",
      style: "one-liner" as const,
    };
    
    tellJoke(narrowJoke); // ok
    
    const wideObject = {
      quote: "~~~",
      style: "one-liner",
    };
    
    tellJoke(wideObject);
    // Argument of type '{ quote: string; style: string; }' is not assignable to parameter of type 'Joke'.
    //  Types of property 'style' are incompatible.
    //    Type 'string' is not assignable to type '"story" | "one-liner"'.
    ```
    

### 읽기 전용 객체

- 변수의 초기값으로 사용되는 객체 리터럴은 let 변수의 초기값이 확장되는 것과 동일한 방식으로 속성 타입을 확장한다.
- as const를 사용해 값 리터럴을 어서션하면 유추된 타입이 가능한 구체적으로 변환된다. 모든 멤버 속성은 readonly가 되고 리터럴은 고유한 리터럴 타입으로 간주되며 배열은 읽기 전용 튜플이 된다.
    - 다음 preferencesMutable 값은 as const 없이 선언되었으므로 string 타입이 되고 수정이 허용된다.
    - 그러나 preferencesReadonly는 as const로 선언되었으므로 해당 멤버 값은 리터럴이고 수정이 허용되지 않는다.
    
    ```tsx
    function describePreference(preference: "maybe" | "no" | "yes") {
      switch (preference) {
        case "maybe":
          return;
        case "no":
          return;
        case "yes":
          return;
      }
    }
    
    // 타입 { movie: string, standup: string }
    const preferencesMutable = {
      movie: "maybe",
      standup: "yes",
    };
    
    describePreference(preferencesMutable.movie); // Error: string은 할당할 수 없다.
    
    preferenceMutable.movie = "no"; // ok
    
    // 타입 readonly { readonly movie: "maybe", readonly standup: "yes" }
    const preferencesReadonly = {
      movie: "maybe",
      standup: "yes",
    } as const;
    
    describePreference(preferencesReadonly.movie); // ok
    
    preferencesReadonly.movie = "no"; // Error: 읽기 전용 속성이므로 할당할 수 없음
    ```
