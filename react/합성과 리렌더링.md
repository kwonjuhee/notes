
합성 패턴([[합성 (Composition)]])을 사용하는 것은 **그저 prop으로 객체를 넘겨주는 것과 같다.** 부모 컴포넌트에서 이미 렌더링된 객체(React element)를 자식 컴포넌트로 전달하는 것이다.

따라서 자식 컴포넌트가 리렌더링되어도 그 객체를 그대로 사용할 뿐 children의 리렌더링과는 관련이 없다.

이 원리를 통해 렌더링 최적화를 적용할 수 있다. [[렌더링 가이드 번역#컴포넌트 렌더링 최적화 기법]]

> 합성 패턴의 모양새가 부모-자식 컴포넌트 관계로 오해할 소지가 있는 것 같다. children prop과 이를 받는 컴포넌트의 관계로 바라보자!


## 부모-자식 관계와 비교

```jsx
function Parent() {
  return (
    <div>
      <Child />
    </div>
  );
}
```

`Parent`에서 반환된 `<Child />`는 `React.createElement(Child, null)`로 컴파일되고 이는 `{type: Child, props: {}}` 형태의 React element를 생성한다.

Parent이 리렌더링될 때마다 createElement가 호출되므로 매번 Child도 함께 리렌더링된다.


## Examples

### 예제 1

```jsx
const Parent = () => {
  return (
  	<Child1>
      <Child2>
      	<Child3 />
      </Child2>
    </Child1>
  )
}

const Child1 = ({ children }) => <div>{children}</div>;
const Child2 = ({ children }) => <div>{children}</div>;
const Child3 = () => <div>저는 막내예요</div>;
```

- Child1이 리렌더링되어도 Child2, Child3의 리렌더링에 영향이 없다.
- Child2는 Parent가 렌더링될 때 생성된 객체이므로 Child1이 리렌더링되어도 `props.children`의 참조 동일성은 유지된다. Child3 또한 마찬가지이다. ([[얕은 비교#props 업데이트 검사]]는 통과할 것)
- Child1, Child2, Child3의 리렌더링 여부는 오직 부모 컴포넌트 Parent에 의존한다.

### 예제 2

```jsx
function App() {
  return (
    <Parent lastChild={<ChildC />}>
      <ChildB />
    </Parent>
  );
}

function Parent({ children, lastChild }) {
  return (
    <div className="parent">
      <ChildA />
      {children}
      {lastChild}
    </div>
  );
}
```

- Parent가 리렌더링되어도 ChildA만 함께 리렌더링된다.


## 컴포넌트 트리 !== 렌더링 관계 트리

예제 1에서 React DevTools로 컴포넌트 트리를 확인해보면 다음과 같다. 컴포넌트 트리는 렌더링 관계가 아닌 중첩된(nested) DOM 트리 구조를 보여준다.

또한 `rendered by`에서 해당 컴포넌트를 리렌더링할 수 있는 컴포넌트들을 보여준다. App 또는 Parent가 리렌더링되면 Child2가 리렌더링된다는 의미다. Child1은 존재하지 않는다.

따라서 DOM 트리나 컴포넌트 트리를 보고 리렌더링 관계를 판단하면 안된다.
