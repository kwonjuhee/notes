## 합성 이벤트 (Synthetic Event)

- React는 **크로스 브라우징을 위해** 브라우저의 native 이벤트 객체를 한번 래핑한 `합성 이벤트(Synthetic Event)`를 사용한다. (Native Event만으로는 모든 브라우저에서 일관되게 처리할 수 없다?)
- 이벤트 핸들러는 native event가 아닌 synthetic event의 인스턴스를 전달받는다.
- 이벤트가 모든 브라우저에서 동일하게 동작한다는 점만 제외하면 native 이벤트와 동일한 인터페이스를 가지고 있다.
	```
	boolean bubbles
	boolean cancelable
	DOMEventTarget currentTarget // 이벤트 리스너가 적용된 요소(root DOM node)
	boolean defaultPrevented
	number eventPhase
	boolean isTrusted
	DOMEvent nativeEvent // native 이벤트를 가리킨다
	void preventDefault()
	boolean isDefaultPrevented()
	void stopPropagation()
	boolean isPropagationStopped()
	void persist()
	DOMEventTarget target // 이벤트가 발생한 요소
	number timeStamp
	string type
	```


## React의 이벤트 처리 방식

React에서는 vanilla javascript 방식처럼 해당 요소에 이벤트 핸들러를 붙이는게 아니라 root 요소에 붙인다. (버블링, 이벤트 위임 방식)

### 이벤트 핸들러 생성

1. 앱이 시작되면 Native Event 목록을 이용해 React 이벤트 핸들러 프로퍼티와의 매핑 테이블을 생성한다. (ex. `onClick` - `click`)
2. createRoot가 실행되면 모든 종류의 Native Event에 대해 루프를 돌면서 이벤트 리스너(`dispatchEvent`를 호출하는)를 root 요소에 붙인다.

### 이벤트 핸들러 트리거

1. 이벤트가 발생하면 root에 붙여둔 이벤트 리스너가 이를 인지하여 Native Event에 매핑되는 Synthetic Event로 변환한 후 `dispatchEvent` 메소드를 호출한다.
2. 이벤트 객체로부터 `target` DOM 노드를 식별하고 `[internalInstanceKey]`로 해당 DOM 노드의 Fiber 노드 인스턴스를 확인한다.
3. 이벤트의 target Fiber 노드부터 root 노드까지 Fiber tree를 올라가며 순회한다. 이때 host 컴포넌트이고 발생한 이벤트 타입에 맞는 리액트 이벤트 핸들러 prop을 갖는 Fiber 노드를 발견하면 이 이벤트 리스너를 `dispatchQueue`에 넣는다. (매핑 테이블 이용)
4. root 노드에 도착하면 `dispatchQueue`를 순서대로 실행한다. 이때 Fiber 인스턴스가 중복(이벤트 중복 여부)인지 확인하고 stopPropagation 여부도 검사한다.

>🔎React는 DOM 노드에 `[internalInstanceKey]`라는 동적 키 아래에 Fiber 노드에 대한 참조를, `[internalPropsKey]`라는 키 아래에 props를 배치한다.

### 장점

- 대규모 애플리케이션 트리에서 성능상 이점이 있다.
- 이벤트 재생과 같은 새로운 기능을 추가하기 쉽다.
	- [이벤트 재생(event replaying)]([https://twitter.com/dan_abramov/status/1200118229697486849])


## stopPropagation 사용시 주의할 점

stopPropagation은 SyntheticEvent에서만 유효하다. Native Event가 DOM에서 버블링되는 것은 막을 수 없다.

```jsx
const App = () => {
  useEffect(() =>{
    document.addEventListener('click', () => console.log('document'));
  }, []);

  return (
  <div onClick={() => console.log('outer')}>
    <div onClick={(e) => {
      e.stopPropagation();
      console.log('inner');
    } />
  </div>
  );
}

// inner, document 출력
```


## React 17부터 달라진 점과 이유

<img src="https://user-images.githubusercontent.com/62097867/213772259-ee3a095e-70f5-4f03-bd86-82dc9c5249e5.png" width="600px" />

React 17부터 document가 아닌 root 요소에 이벤트 리스너를 붙이게 되었다.

이는 React와 non-React 또는 다른 버전의 React 코드 베이스를 합쳐서 사용해야 하는 경우에 각각 독립적으로 이벤트 핸들링을 처리하기 위해서이다.

ex. app의 외부 셸은 jQuery로 작성되었지만 내부의 최신 코드가 React로 작성된 경우, React 코드 내부의 `e.stopPropagation()`이 jQuery 코드에 도달하지 못하게 한다.

ex. react를 걷어내고 싶다면 이벤트 전파를 중단하지 않고 외부 셸부터 React에서 jQuery로 점진적으로 변경할 수 있다.
