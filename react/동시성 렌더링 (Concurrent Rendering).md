
## 동시성 (Concurrency)

### 동시성이란

- 동시성은 **독립적으로 실행되는 프로세스들**의 조합이다.
	- 병렬성은 연관된 복수의 연산들을 동시에 실행하는 것이다.
- 동시성은 여러 일을 **한꺼번에 다루는 문제**에 관한 것이다.
	- 병렬성은 여러 일을 한꺼번에 실행하는 방법에 관한 것이다.

> 💡 즉, 동시성 이란 2개 이상의 독립적인 작업을 잘게 나누어 **동시에 실행되는 것처럼 보이도록** 프로그램을 구조화하는 방법이다. 실제로는 하나의 스레드로 작업을 처리하지만 **마치 여러 개의 스레드가 사용되고 있는 것처럼 보이게** 한다.

### 동시성 (Concurrency) vs. 병렬성 (Parallelism)

![[동시성 렌더링 (Concurrent Rendering)-6.png]]

| 동시성 (Concurrency) | 병렬성 (Parallelism) |
| --- | --- |
| 싱글 코어에서도 작동 | 멀티 코어가 필요 |
| 동시에 실행되는 것처럼 보임 (컨텍스트 스위칭 필요) | 실제로 동시에 실행됨 |
| 최소 두 개의 논리적 통제 흐름 (예. 동영상 재생하면서 메모장 쓰기) | 최소 한 개의 논리적 통제 흐름 (예. GPU를 이용해 이미지 출력하기) |

## 동시성으로 해결하려는 문제

### Blocking Rendering 문제

![[동시성 렌더링 (Concurrent Rendering).png]]

브라우저의 메인 스레드는 싱글 스레드이기에 한 번에 하나의 작업만 처리할수 있다.
이로 인해 자바스크립트 파싱을 시작하면 작업이 완료될 때까지 멈출 수 없다.
따라서 리액트 렌더링 연산이 오래 지속된다면 자바스크립트 연산이 길어지면서 렌더링이 블로킹되는 문제가 발생한다.
이는 프레임 드롭이 발생하고 유저 이벤트에 대한 처리가 지연되면서 응답성이 떨어지게 된다.

> [!important]
> 대규모 화면 전환에서도 blocking rendering을 막고 높은 응답성을 유지하는 것이 목표
> 

### 지연 기법을 통해 문제 해결 시도

기존에는 setTimeout 기반의 지연 기법을 통해 문제를 해결하고자 하였다.

- 입력하는 동안 화면을 그리지 않도록 하는 디바운싱
- 입력하는 동안 일정한 주기로 화면을 그리도록 하는 쓰로틀링

하지만 이 또한 결국 렌더링이 시작되면 중간에 중단될 수 없으므로 blocking rendering 문제를 피할 수 없어 불안정한 사용자 경험을 제공하게 된다.

## 동시성 렌더링

- 급한 작업과 덜 급한 작업을 구분하고 작업을 병렬로 배치한다. 일정 시간동안 작업 후 다음 작업에게 메인 스레드를 양보하게 한다.
	![[동시성 렌더링 (Concurrent Rendering)-4.png]]
	![[동시성 렌더링 (Concurrent Rendering)-2.png]]

- 하위 컴포넌트 렌더링 작업을 잘게 나눈다.
	![[동시성 렌더링 (Concurrent Rendering)-3.png]]
- 렌더링 도중에 급한 작업이 발생하면 낮은 순위 렌더링을 멈추고 높은 순위 렌더링과 페인팅을 먼저 수행한다. 그리고 pending 상태의 낮은 순위 렌더링을 리베이스한다.
	![[동시성 렌더링 (Concurrent Rendering)-5.png]]


---

기존 렌더링 방식은 동기식으로 동작.

Concurrent React에서는 렌더링을 시작하고 중간에 일시 중지한 다음 나중에 계속하거나 진행 중인 렌더링을 완전히 포기할 수 있다.

메인 스레드를 차단하지 않고 백그라운드에서 새 화면을 준비할 수 있다.

UI가 대규모 렌더링 작업 중에 있더라도 사용자 입력에 즉시 응답하여 유동적인 사용자 경험을 생성할 수 있음을 의미한다.

궁극적인 목표는 네이티브 앱처럼 높은 수준의 응답성을 구현하는 것

## React가 업데이트를 바라보는 관점


위 화면에서 발생한 업데이트는 두 가지이다.

- `<input />`으로부터 발생한 `text` 상태 업데이트
- 자동완성 API의 응답으로부터 발생한 `<AsyncAutoComplete />`의 자동완성 리스

두 업데이트의 차이를 업데이트의 시작점으로 분류하자면 사용자 인터랙션 / 비동기
렌더링 관점으로 바라보자면 자동완성 UI는 전환(Transition) 업데이트로 추가로 분류할 수 있다.

React는 업데이트를 다양하게 분류하여 생각하려고 한다. 사용자 인터랙션, 비동기, 전환으로부터 발생한 업데이트를 모두 다르게 간주하며 처리하는 방식 또한 업데이트 성격에 따라 다르다.

사용자 또한 사용자 인터랙션/전환에 대해 기대하는 반응 속도가 다르다.
사용자 인터랙션에 대해서는 즉각적인 반응을 기대하고 그렇지 않다면 뭔가 잘못되고 있다고 느낄 수 있다.
반면 A0 -> A1의 전환은 느릴 수 있다고 무의식적으로 인지하며 모든 전환에 대해 즉각적인 반응을 기대하지 않는다.
따라서 전환 업데이트는 반영이 조금 느리더라도 UX를 크게 해지지 않는다고 판단할 수 있다.


이렇게 리액트는 업데이트를 분류해서 바라보고 각각 우선순위를 두고 있으며 동시다발적으로 발생하는 업데이트 사이에서 렌더링 대상을 선별하고 렌더링 방식을 결정하는 데에 기준으로 사용한다.
