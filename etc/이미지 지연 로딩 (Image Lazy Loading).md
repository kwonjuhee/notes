## 이미지 지연 로딩이란

> 이미지들이 **실제로 화면에 보여질 필요가 있을 때 로딩하게 만드는 기법**

브라우저는 \<img> 태그의 src 속성이 있다면 HTML 내 몇번째 이미지이든 뷰포트 밖에 있든 상관없이 무조건 이미지를 로드한다. 이미지가 많다면 사용자가 보지 않는 이미지 또한 많아질 것이다. 이를 초기에 모두 로드할 필요는 없다!!

👍 **성능 향상**

페이지 초기 로딩시 필요로 한 이미지의 수를 줄여 리소스 요청을 줄일 수 있다. 리소스 요청을 줄이는 것은 **제한된 네트워크 대역폭의 경쟁을 줄이는 것**으로 **다른 리소스들을 더 빠르게 처리**할 수 있다. 이는 **웹 사이트 로딩 시간을 감소**시켜 사용자가 더 빨리 페이지를 이용할 수 있도록 한다.

👍 **비용 감소**

리소스 요청 비용은 전송 바이트 수에 비례한다. 페이지 내에서 **전달할 총 바이트 용량을 줄이면** 비용을 감소시킬 수 있다.

페이지를 이탈하거나 페이지의 제일 상단에만 서비스를 이용하는 유저에게 효과적이다.

## 적용 방법

- `<img>` 태그에 `loading="lazy"` 추가
    - 뷰포트 영역에 근접할 때 이미지를 로드한다.
    - ⚠️ 이미지 높이 값이 없으면 동작하지 않는다.
- Intersection Observer API 이용

## 이미지 로딩을 위한 버퍼 시간 추가하기

### 문제점

뷰포트의 하단 부분과 이미지의 상단 부분이 만나는 시점에 이미지 로딩이 트리거된다. 사용자가 빠르게 스크롤하는 경우에 placeholder가 뷰포트에 들어오게 되고 사용자는 로딩되는 약간의 시간을 기다리게 된다. 이러한 딜레이는 사용성에서 좋지 않다.

### 해결 방법

이미지가 뷰포트에 들어왔을 때 완전히 로딩되어 보여지도록 로딩이 트리거되는 시점을 앞당기자! 이미지가 뷰포트에 들어올 때 로딩하는 대신, 뷰포트에 들어오기 직전에 로딩하도록 한다.

Intersection Oberver API에서는 ‘root’와 ‘rootMargin’ 파라미터를 사용하여 트리거 시점을 조정할 수 있다.

## ⚠️ 모든 이미지에 lazy load를 적용하지 않기

웹 페이지 상단의 이미지는 자바스크립트가 적용되고 동작할 때까지 보여지지 않을 것. 초기 로딩시에는 로딩이 줄어들지만 사용성을 해칠 수 있다. 

**lazy loading이 적합하지 않은 case**

- 웹 페이지 시작시 뷰포트에 있는 이미지
    - 페이지 상단 이미지나 마케팅 배너, 로고 등과 같은 이미지는 페이지가 로딩되자마자 사용자에게 보여져야 한다.
    - 모바일과 데스크톱은 화면 크기가 달라 화면에 보여지는 이미지 수가 다르다. 따라서 디바이스 타입을 고려할 필요가 있다.
- 뷰포트에서 멀지 않은 이미지
    - 이러한 이미지들은 뷰포트에 완전히 들어가기 전에 미리 로딩을 하는 것이 사용성에 좋다.
- 페이지가 길지 않은 경우
