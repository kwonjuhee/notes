에러 처리 코드가 일관되지 않으면 관련 코드가 산발적으로 흩어져 유지 보수 비용 증가

1.  에러가 발생해도 사용자가 앱을 사용하는데 최대한 지장이 없어야 한다.
    
    페이지 정보들을 불러오던중 일부 정보만을 불러오지 못했을 뿐인데 전체 페이지가 에러 페이지로 대처된다면 정상적으로 불러온 정보들도 보지 못할 것이다. 사용자가 정상적으로 앱을 이용할 수 있음에도 이용하지 못하도록 강제한 것이기 때문에 사용자 경험을 떨어뜨린다.
    
2. 사용자는 에러 발생 사실을 인지할 수 있어야 한다.
    
    사용자가 재시도를 할 수 있도록 에러가 발생했다는 사실을 인지할 수 있도록 해야한다.
    

# 기준 생각해보기

## 에러를 어디서 처리할 것인가?

에러가 전파되는 순서는 다음과 같다.

1. 에러가 최초로 발생한 함수 (api 요청 관련 함수)
2. 1번 함수의 반환값을 표현하는 컴포넌트
3. 2번 컴포넌트를 감싸는 에러 바운더리

1번에서 모든 에러를 처리하기에는 상황에 따른 유연성이 너무 부족하다. console.error 정도의 역할만 맡도록 한다.

3번에서는 폴백 컴포넌트를 렌더링하여 무조건 에러 전파가 끊어져야 한다.

## 에러를 어떻게 알릴 것인가?

1. 에러가 발생한 컴포넌트만 에러 화면으로 대체하기
2. alert, snackbar 등을 강제로 보여주기
3. 1번과 2번 모두 사용하기

1번 에러는 에러 바운더리에서 처리 가능하다.

# 시나리오

## 404에러 처리

- 잘못된 URL 정규식을 방문했을 때
    - **catch-all route** 사용 👉 404페이지 라우팅
- 유효한 URL 정규식이지만 잘못된 API 호출일 경우
    - 응답 코드를 state로 관리하여 에러 처리를 한다.
    - 최상위 컴포넌트로 렌더링되어야 한다.
    - API를 호출하는 모든 컴포넌트에서 반복 로직이 발생한다.
    - 404 이외의 다른 에러를 처리하려면 더 많은 코드와 로직을 추가해야 한다.

# 방법 생각해보기

## “redirect” 하기

👎 사용자가 현재 위치의 컨텍스트를 잃게 된다.

👎 기존의 URL이 변경되므로 어떤 것을 못찾았는지 알 수 없다. 404 페이지가 표시되는 동안 잘못 입력했던 원래 URL이 유지되는게 좋다.

## “hook” 사용

- API 요청하는 custom hook을 사용한다.
    - url을 인자로 받아 응답 데이터와 status 코드를 반환한다.
    - custom hook을 호출한 컴포넌트에서 status 코드에 따라 에러 처리하기
- 반복 로직은 해결
- But 여러 응답 코드를 다루는 것은 여전히 각 컴포넌트별로 처리

## “render-props” 사용

```jsx
const Query = ({ url }) => {
  const { data, statusCode } = useQuery({ url });

  if (statusCode === 404) {
    return <Page404 />;
  }

  // ... 등 여기서 여러 HTTP 응답 코드 처리

  return children({ data });
};
```

- 반복 로직 해결, 여러 응답 코드를 공통으로 처리 가능
- But 최상위 컴포넌트로 렌더링할 수 없다. 다른 컴포넌트와 함께 전체 UI의 일부로 렌더링될 것.

## “top-level state” 사용

- 다른 페이지가 렌더링되기 전에 404 페이지를 렌더링한다.
- 응답 에러 코드를 최상위 컴포넌트에 알릴 수 있도록 상태 관리 라이브러리를 이용한다.
- 상태 코드에 따른 처리를 top-level에서 한다.

```jsx
// 컨텍스트를 사용해 컴포넌트 트리를 낮춰 오류 페이지를 표시한다
const ErrorStatusContext = React.createContext();

// 앱의 핵심 기능을 랩핑하는 최상위 컴포넌트
const ErrorHandler = ({ children }) => {
  const history = useHistory();
  const [errorStatusCode, setErrorStatusCode] = React.useState();

  // 사용자가 새 URL을 탐색할 때 마다 이 상태코드를 "제거" 해야한다. 그렇지 않을 경우 사용자는 오류 페이지에 영원히 "갇히게" 된다.
  React.useEffect(() => {
    // 현재 위치의 변경 사항을 하는 리스너
    const unlisten = history.listen(() => setErrorStatusCode(undefined));
    // unmount될 때 리스너 제거
    return unlisten;
  }, []);

  // 컴포넌트를 렌더하는 부분이다.
  // API 오류와 일치하는 errorStatusCode가 있으면 오류 페이지를 렌더링한다. 오류 상태가 없다면 자식 컴포넌트를 정상적으로 렌더링한다.
  const renderContent = () => {
    if (errorStatusCode === 404) {
      return <Page404 />;
    }

    // ... 다른 HTTP 코드는 여기서 관리

    return children;
  };

  // 성능상의 이유로 useMemo로 랩핑. 더 궁금하다면 링크 확인
  // https://kentcdodds.com/blog/how-to-optimize-your-context-value/
  const contextPayload = React.useMemo(() => ({ setErrorStatusCode }), [
    setErrorStatusCode,
  ]);

  // 컨텍스트의 값을 컴포넌트에 노출하는 동시에 화면에 적절한 컨텐츠를 렌더링
  return (
    <ErrorStatusContext.Provider value={contextPayload}>
      {renderContent()}
    </ErrorStatusContext.Provider>
  );
};

// 컨텍스트 값을 빠르게 읽을 수 있는 커스텀 훅이다.
// 빠른 import를 위해 여기서만 허용된다.
const useErrorStatus = () => React.useContext(ErrorStatusContext);
```

```jsx
const App = () => {
  return (
    <BrowserRouter>
      <ErrorHandler>
        <Switch>
          <Route exact path="/" component={IndexPage} />
          <Route exact path="/dogs/:breed/" component={DogPage} />
          <Route component={Page404} />
        </Switch>
      </ErrorHandler>
    </BrowserRouter>
  );
};
```

## “history API” 사용

- state에 statusCode를 저장한다.
    - 다른 위치로 이동할 때 state를 정리할 필요가 없다.
    - 이전으로 이동하기를 눌렀을 때 API 요청을 새로하지 않아도 404페이지를 자동으로 보여준다.
    - 원하는 어떤 키든 저장하고 관리할 수 있으므로 구성이나 확장면에서 뛰어나다. 데이터를 props로 전달하여 오류 페이지 구성 요소로 사용 가능하다.

```jsx
const ErrorHandler = ({ children }) => {
  const location = useLocation();

  switch (get(location.state, "errorStatusCode")) {
    case 404:
      return <Page404 />;

    // ... 다른 타입의 상태 코드를 처리한다

    default:
      return children;
  }
};
```

```jsx
const useQuery = ({ url }) => {
  const history = useHistory();
  const [apiData, setApiData] = React.useState();

  React.useEffect(() => {
    fetch(url)
      .then((data) => data.json())
      .then(({ code, status, ...apiData }) => {
        if (code > 400) {
          history.replace(history.location.pathname, {
            errorStatusCode: code,
          });
        } else {
          setApiData(apiData);
        }
      });
  }, [url]);

  return { data: apiData };
};
```
